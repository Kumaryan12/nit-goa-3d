# Chapora movie nights

The screening feature and fixed welcome-film loop are part of the 15 October 2026 release. Publish matching backend and Pages frontend versions together.

Open **Screenings** in the campus toolbar or **Movie screenings in Chapora** in the Seminar Complex details. The owner-selected [Welcome to National Institute of Technology Goa](https://www.youtube.com/watch?v=GQ6iaPxYqao) is the only screening source. It is preloaded and plays on repeat without an online host. The server rejects source replacement and ending the program, including commands from an older admin client. Only the verified administrator can pause, resume, restart or seek within this video. An intentional pause remains paused until resumed.

The server and viewers share a repeating 95.434-second timeline, based on the video’s published track duration. Late arrivals and returning tabs catch up to that timeline. The server folds elapsed time back into the film on every loop; it continues across host disconnection and beyond four hours. Restarting the server begins a fresh loop. The official YouTube single-video loop and playlist parameters repeat only the pinned video locally; periodic synchronization keeps viewers on the shared timeline. Natural end events never pause the program for everyone.

Visitors choose **Join screening** to take one of 32 assigned Chapora seats in the four front rows. Each row reserves the eight centre chairs; assignment begins nearest the screen and centre aisle. Avatars face the screen from their actual chairs. This shares the existing 32-person campus capacity. Seats are published from the same terrain and hall layout as the browser, rather than supplied by a client. Ordinary actions, vehicles and jump controls are unavailable while watching. Leaving returns the local avatar to the clear centre aisle; choosing another destination honours that destination. Nearby visitors see seated avatars in `seminar:0`. Existing privacy filtering still hides their coordinates from other buildings and distant visitors.

The movie displays on the physical stage screen using one 16:9 HTML player. A dedicated, level camera faces the centre of the screen from near the assigned front row, with framing fitted to the current screen size. The local avatar is hidden only from its own viewing camera; other visitors still see it seated. Campus tools, location shortcuts, the minimap and the general view dock are hidden while seated and restored on leaving. The movie’s own Cinema view control remains available. Screening controls collapse into a compact sound/fullscreen/leave strip, with chat and owner controls still available through Expand. **Cinema view** enters fullscreen on supported browsers. Each viewer starts muted and explicitly enables sound, with personal volume and mute in both the panel and player. Closing/minimising controls keeps the screening running. Hidden tabs pause local decoding and catch up when visible again. Leaving or disconnection releases the local player and media resources. Reconnection attempts to reclaim an available seat rather than assuming the former seat is still free.

The pinned source streams directly from YouTube to each viewer, without passing video data through Render or the voice TURN relay. The app does not upload or download a copy of the movie. Each viewer’s internet usage still applies. Browser autoplay can require a tap, and sound stays muted until explicitly enabled. YouTube controls its own player, ads, buffering and availability; the application does not select any other content or provide another source field.

Quiet chat and four reactions are available only to seated members. Chat is rate limited and bounded to 40 messages from the current film. Nonparticipants receive screening status without chat history. Existing moderation message removal also clears that sender's screening chat.

YouTube uses its official IFrame API, privacy-enhanced embed host, an exact parent origin and an explicit origin-only referrer policy. CSP adds only the required YouTube script and frame origins. The API is loaded only for a joined viewer. Embedding-disabled, deleted, restricted or blocked videos show a playback error. YouTube ads, buffering and device autoplay rules can interrupt an individual viewer; this is shared best-effort playback, not a guarantee of frame-perfect distribution. For an event, rehearse the chosen film with separate accounts and actual audience devices before starting.

References: [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference), [HTML media autoplay](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay), [Drei HTML surfaces](https://drei.docs.pmnd.rs/misc/html).

## Local rehearsal

The loopback-only fixture uses synthetic identities and cannot run with `NODE_ENV=production`. It is not imported by the application or included in production builds.

1. Run Vite on port 5180: `VITE_FIREBASE_API_KEY= VITE_CAMPUS_SERVER_URL= npm run dev -- --host 127.0.0.1 --port 5180 --strictPort`.
2. Run `node --experimental-strip-types tests/fixtures/screening-server.mjs` on port 5182.
3. The rehearsal starts with the same repeating welcome film. Open `/tests/fixtures/screening-preview.html` for the owner and append `?who=alice` or `?who=bob` in other tabs for audience members. Each identity can occupy only one tab. Use a regular Chrome or Safari window for media rehearsal; VS Code’s integrated preview blocked YouTube playback in our local check.
4. The panel reports connection failures, duplicate identities and unavailable screening support, with an explicit reconnect control. Transport interruptions retry automatically; hot reload disposes the old socket.
5. Join seats and check natural repetition, late joining, pause/resume, owner restart/seek, volume, fullscreen, chat and leaving. Playback must continue when the owner disconnects. The fixture uses the real room, protocol, hook, panel, player and hall geometry; it does not bypass production Firebase verification.

Automated coverage includes source replacement rejection (including by the owner), automatic preparation, exclusive seat allocation/reuse, exact loop boundaries, multi-loop catch-up, pause/resume, restart/seek authorization, host-independent playback, chat isolation, schema validation, blocked/buffering startup and actual authenticated WebSocket peers.

Validation: all 578 regression tests and the production Pages build pass. In regular Chrome, the pinned welcome video played with sound on the hall screen and passed its natural end, restarting at the opening while the shared timer wrapped from 1:31 to 0:07. No manual restart was used. Separate-account and physical-device rehearsal remain useful before a public event.

Viewing correction validation: 580 regression tests and the production Pages build pass. New geometry checks cover all 32 physical seat assignments and full-screen-corner framing at desktop, landscape and portrait aspect ratios. Local Chrome checks verified the straight 16:9 stage view and a 390 × 844 portrait viewport.
