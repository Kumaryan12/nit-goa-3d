# Mobile experience and verification

Phones start with side panels and the minimap hidden, unless a visitor has saved a layout. Walking keeps Overview and a compact Tools button at the top; search, people, games, night mode and graphics remain available in Tools. The lower controls retain transport selection, jump, pause, building entry and shared buggy boarding. Narrow-screen movement/action controls have separate backgrounds so the avatar is visible between them. Distant campus place captions are hidden while walking on narrow screens; the Overview labels and search remain available.

Phone inputs use 16 px text, primary controls have 44 px touch targets, and scene controls account for safe-area insets. The scene uses dynamic viewport height and asks supporting browsers to resize content around their keyboard. Landscape places the header to the right of movement controls; short portrait viewports retain their normal layout. Existing pinch and scroll zoom both remain available. Focus view and the fullscreen fallback still work without native fullscreen support.

Coarse-pointer and low-core devices start with the Smooth graphics budget. Automatic graphics can lower pixel ratio to 0.65, shadow maps to 512 px and shadow updates to 6 Hz after sustained low frame rate, and recover with the existing cooldown. Automatic phone quality stops at the ordinary Smooth budget. Antialiasing is disabled on these compact devices to reduce GPU work. Geometry, building access, collisions and trees remain available. A restored WebGL context refreshes cached shadows; hidden pages pause rendering.

For a repeatable local check, run `VITE_FIREBASE_API_KEY='' npm run dev`, then open `/tests/fixtures/mobile-preview.html`. The fixture renders the actual campus in selectable 320 × 568, 390 × 844 and 844 × 390 frames using the same published map as production. It reports viewport bounds and page overflow. `/tests/fixtures/multiplayer-preview.html` animates two/32 synthetic visitors through the actual remote rendering buffer. These fixtures are excluded from production builds, require development mode without Firebase configuration, and provide no server identity or authentication bypass.

Checked in Chrome: all three frame sizes loaded the campus without document overflow and kept header, movement and view controls within their viewport. Bicycle selection and opening/closing Tools worked. The crowd fixture retained two/32 actors while changing camera distance. The full regression suite passes 399 tests; production build and typecheck pass.

Physical-device rehearsal remains necessary: use separate Google accounts on iOS Safari and Android Chrome, join in Walk mode at Main Entrance, confirm both names/avatars immediately, move/cycle together, switch apps and return, rotate the phone, open search/chat with the keyboard, and pinch the scene while using the joystick. Check sustained FPS and thermal behavior on a lower-end phone. A desktop browser viewport cannot validate phone GPU speed, touch hardware, Google popup behavior or mobile-network conditions. The single free Render instance can still cold-start; no host upgrade or room capacity increase is included.
